# 临近加工偏好的学习实施计划

日期：2026-10-15。状态：讨论后的修订计划；本文件不代表模型、训练集适配器或新生成器已经实现。

## 1. 目标与边界

新零件仅提供本件事实及已确定的通用工艺条件，自动生成硬合法候选，由训练好的方案评分器排序。临近特征同序是否合理，优先作为待学习的偏好，不默认增加最近邻禁止同序规则、人工 pair 清单依赖或临近固定软惩罚。

H1–H7 继续执行。方向分量暂保持独立报告；此前提议的新权重尚未选定，本路线不自动启用它。模型输出是推荐依据，不能提供未建模工艺问题的硬安全保证。

N1 不再作为正式推理主路线。训练零件上的具体问题 pair 标注可以帮助定位学习目标，但不是新零件的必要输入。若以后有可验证且推理时可获得的通用硬规则，再单独明确其适用条件。

## 2. 已核查的表示能力

当前代码证据：

- src/graph/builders.py 的 add_geometric_relations 使用真实曲线边界距离构建 Graph2，默认 k=8。
- src/graph/schema.py 的 GeometricEdge 包含 distance_norm、relative_dx_norm、relative_dy_norm。
- 同文件 PlanOverlay.edge_features 提供 same_station、station_delta、abs_station_gap；PlanGraph.plan_edge_features 按图中边计算这些字段。
- 节点已有 Operation 静态信息与当前候选 Station 状态。

因此，已连接的邻近 pair 可以同时表达动作类型、几何距离及是否同序。现有 k=5 诊断是审阅工具，不替换冻结 Graph2 的 k=8。模型能获得这些字段，不等于已学会工艺偏好。

下一步新增训练 tensor adapter 时明确传递现有边特征；不只传 adjacency 而遗漏 same_station 或距离。几何缺失、目标 pair 不在图边上，以及全件归一化距离能否表达跨零件相关尺度，都要列入覆盖审计；不足时再提版本化特征方案，不静默改 Graph0/1/2。

验收：同一 static graph 上改变合法方案分配，图结构不变，受影响边的 same_station 与工序差正确改变；不含 expert station、盲号或 reference 身份。

## 3. 先补有效训练比较，不自动补标签

当前 24 对截图评审有 18 个 D、6 个明确 A/B；6 个 A/B 都涉及同一参考方案，不能当成 24 个有方向的偏好样本，也不足以证明模型已经能分辨临近工艺原因。

按既有标签政策：A/B 进入第一版成对排序损失；D 保留为双方有明显问题的反馈，不能转换成 A/B、平局、具体 pair 冲突标签或重复的独立样本。第一版不擅自增加 D 对应的可接受性分类损失。

后续训练数据采集采用两类比较：

1. **整体比较**：无 reference 生成的、多样的硬合法候选之间比较，覆盖整套方案质量。
2. **局部对照比较**：针对系统自动找到的临近 FLANGING–IRREGULAR_PUNCH pair，在 H1–H7 下分别求同序与异序方案，尽量减少其它 Operation 的分配变化。

局部对照仅用于采样，不预先认定异序胜出。若一个分支硬不可行，记录后跳过；若必须联动移动多个 Operation，展示并记录所有变化，不能声称只改变一个因素。优先覆盖不同距离、局部结构和可行 Station 组合，不只围绕一种失败模板采样。

专家仍评完整方案，可补充可选原因：“临近加工问题”“其它工艺问题”“不能确定”；必要时点选涉及的 Operation。原因和 pair 定位单独存储，不进入推理输入，不自动转成硬规则，也不把整方案胜负复制成每个局部 pair 的标签。

训练零件允许人工监督；验证/测试零件的评审仅在候选和预测固定后用于评估，不反过来调整该轮生成或模型。局部对照可作为测试评分器的固定挑战集，但不能替代正式生成候选上的端到端评价。

## 4. 执行顺序和交付物

### A. 表示与数据审计

核查 O131/O203 和 A02/A06/A08 中相关 pair 的 Graph2 覆盖、边距离、同序状态；核实截图答案来源及比较方向；导出唯一方案、比较数、标签分布和规则版本。输出覆盖报告，不自动生成真值。

### B. 无 reference 候选和局部对照入口

沿用 REFERENCE_FREE_INFERENCE_AND_TRAINING_PLAN.md 的输入隔离与新生成器计划，以当前 H1–H7 为规则基线。新增可缺少专家答案的事实入口，复用纯硬模型，独立复核所有候选。局部对照构造器作为训练采样工具，和正式生成入口分开。

正式生成保留候选多样性；不事先把所有临近同序方案过滤掉，否则既无法检验模型的区分能力，也可能删掉合理安排。不使用专家负载 G1、专家距离分档或专家 warm start。生成预算、数量和筛选参数在该阶段实施时明确配置，不把旧参数无说明地搬入。

### C. 训练零件评审

先以 P001 检查采样、显示和标注流程，再在其它训练零件采集比较。每批先输出覆盖缺口，再决定补审对象；不把“每件固定若干对”当作充分监督保证。旧 24 对及盲号原样保存，新采样产生独立批次。

### D. 小模型基线与 GNN

按现有训练计划实现统一方案评分 Q(G(P))。同一评分器分别计算 s_A、s_B，以明确 A/B 标签训练分数差，不使用 SoftPenalty 制造标签。

先比较固定启发式对照与可训练的小模型基线，再比较 Graph0/1/2。模型消息传递必须实际使用已有边属性。可在训练/验证范围增加“屏蔽几何边的动态方案属性”的消融，检查其对局部对照的贡献；这只是模型实验，不改变存储的冻结图定义。单项消融不能直接证明因果或工艺理解。

如以后希望让 D 参与可接受性预测，另立标签与任务设计，并收集明确的可接受/不可接受监督；不能仅靠相对 A/B 胜负把获胜方案视为绝对合格。本阶段不实现该扩展。

### E. 跨零件评价

沿用五零件外层留一、内层验证。一个零件的全部方案与局部对照留在同一 split；测试零件专家信息在预测冻结后才开放。

分别报告整体 A/B 排序表现、带专家标签的局部对照表现，以及正式候选 Top-K 的新盲评结果。候选里是否包含有价值方案和排序器能否找到它要分开报告。P001 已用于规则设计，相关结果必须注明开发暴露；未来还需真正未参与开发的零件验证泛化。
