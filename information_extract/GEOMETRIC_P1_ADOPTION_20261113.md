# 几何连接树正式替代 P1 人工影响区输入

用户于2026-11-13明确确认：“这就是我想要的设计啊，折弯影响区就是它的不成熟产物，可以正式用几何连接树替代原P1了”。从本次起，`geometry_p1.v1` 为新分配流程采用的正式 P1；此前“只作候选、尚未采用”的记录属于历史阶段。

## 生效定义

几何连接树以实际材料区域为节点、折弯连接为边。对于某个折弯，从其 child 材料区域向下遍历，得到被带动材料域；以该域内刚性材料实体体积之和作为大小量。它不是 H7 动作父子树，也不读取 Sheet5 人工面积或区域父子链。

保留原 P1 的偏好形式：大小比超过1.15才比较；较大材料域先于较小材料域加工时记反向，同序不罚；由现行硬先后决定的动作对不参与偏好计数。P1=反向对数/可比较对数。若完整几何覆盖但没有可比较对，记0且明确不适用；缺几何、几何断开或输入不匹配则报错，不静默记0、不回退旧面积。

当前接入的全方案评分基于 `neighborhood_penalty.v0.2`：P5优先，次级P1权重0.30、额外间隔0.20、动作分散0.50。保留原阈值、权重、分组及选择规则，没有误用更早v0.6的0.45面积权重。H6停用，H1–H5/H7保留。评分结果中的`area`是兼容既有求解器接口的槽位名称，实际metric明确为`geometric_carried_material_volume`。

当前材料参考为全部去料和局部成形完成后的共同材料，包含刚性板面与STEP局部端态，不包含有限宽折弯带。这是已采用的工艺偏好模型，不表示已证明制造安全、力/时间模型或质量严格守恒。曲线折弯、多步折弯的材料域仍须有明确支持，不能从一个操作编号强行套用单关节树。

## 正式实现

- `three_d/geometric_p1.py`：几何树完整性校验、带动域编译、P1计算、`GeometryScorer`。
- `three_d/allocation_policy.py`：无原Sheet5事实入口与H6禁用。
- `scripts/run_geometry_allocation.py`：当前评分/生成入口，支持`score`与`generate`。
- `tests/test_geometric_p1.py`：正式评分、求解器一致性及隔离回归。

`GeometryScorer`向CP-SAT提供同一几何比较模板，独立评分也用该模板的材料量；复用原P2、分散上下界和P5实现。冻结源码不改，旧实现与旧命令仍供历史复现。已接入完整候选生成，不再仅有单折弯邻域实验。

编译得到`material_basis.json`，含59个带动域、60个区域体积、材料参考、语义事实指纹及自身指纹。重用时检查事实一致及几何覆盖，排除缺失、重复、断开、多父节点、非有限体积和指纹损坏。输入几何对应别的事实时必须重建材料域，不能继续套用。

首次编译会核对既有模型来源；之后可用`--basis`直接评分或生成。原Sheet5删除、XML损坏以及专家列填入错误值均不影响事实指纹或正式分数。原工作簿整体哈希只用于来源追踪，编译材料域的运行时适配依据是无Sheet5/专家的语义事实指纹。

## 本轮实际执行

1. 对冻结16方案进行独立评分，写入`outputs/geometry_allocation_v1/P001`。59折弯、1451可比较对；与旧实现逐方案比较，P1、P2、分散项、P5与次级总分的精确有理数全部一致。最终一次评分运行12.94秒。
2. 使用编译几何域独立生成64候选，选出16方案，写入`outputs/geometry_allocation_v1_generated/P001`。未使用旧候选作种子/提示，未读取专家分配；P5最小值0已证明。最终一次生成运行15.02秒。新方案身份、排序为独立输出，未覆盖冻结集合。
3. 求解器目标与独立评分精确一致。另用人工测试的等体积域消除所有P1比较对，确认评分和CP目标都会改变，避免只更换报告标签而仍使用旧面积。
4. 33项相关测试通过；包括硬约束保留、Sheet5/专家隔离、损坏几何拒绝、完整旧评分等价及材料树校验。未运行全仓测试。两页HTTP200，无浏览器UI或computer-use。
5. 评分与生成分别记录458/111个输入/实现文件指纹，运行期间和交付前复核一致。保护清单103项匹配，5项既有人工更新/P004原图迁移差异继续如实保留，期望哈希未改。

本轮没有对新生成64方案重新跑三维运动干涉；几何P1的正式采用与三维制造可行性检查是不同职责。GNN尚未实现，不生成真实质量标签。

## 使用方式

从仓库根目录运行：

```powershell
# 以P001模型编译材料域，对冻结16方案进行独立新评分
.venv/Scripts/python.exe -B -X utf8 -m information_extract.scripts.run_geometry_allocation

# 使用几何域生成新候选（64池/16入选），输出至独立目录
.venv/Scripts/python.exe -B -X utf8 -m information_extract.scripts.run_geometry_allocation --mode generate --basis information_extract/outputs/geometry_allocation_v1/P001/material_basis.json --output information_extract/outputs/geometry_allocation_v1_generated/P001
```

可用`--input`、`--viewer`、`--plans`、`--basis`、`--output`指定输入；其它零件须先提供匹配并受支持的材料模型，不自动回退P001。
