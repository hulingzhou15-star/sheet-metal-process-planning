# 动作标注与统一几何整理 v2

2026-10-19。本次所有实现与产物位于 information_extract，根项目契约保持冻结。

## 用户流程

1. 逐个选择图元、填写动作信息，创建动作并保存标注。允许规则尚未支持、引用尚未补齐等草稿状态。
2. 解释完整张图后勾选“整图动作解释完成”，点击“整理几何”。该步骤检查动作字段、显式引用、配对和来源，再按类型运行几何处理。
3. 查看每个动作的路径数量和问题。一般折弯跨度、折桥外围范围需要核对确认；曲线折弯保留来源并报告规则待定。
4. 保存整理结果，导出检查包。符合既有表示的几何进入 Sheet2/Sheet5；多轮廓、新类型及待定线形另存完整 JSON。
5. 补齐 Sheet3/4 及其它检查项，完成旧数据契约与 H1–H7 校验后才生成正式表。

未解释的图元仍在覆盖统计中；动作数正确不能替代覆盖检查。折桥内部辅助线仅在外围已确认且整理有效后收纳，所以允许先整理再核对剩余图元。未处理图元不会被偷偷忽略，正式输出仍要求覆盖完整。

### 连续创建与编辑模式修正

点击“创建动作，录下一个”成功后，保留新动作的绑定，清空当前图元选择、编号与其它表单字段，并进入下一动作。失败时保留草稿；编辑已有动作后点击“应用标注修改”则继续编辑该动作。保存/检查等内部应用流程不会意外切换编辑对象。

来源数量明确区分“本次已选”与“已应用绑定”。已有动作的临时选择只有应用后才写入项目状态，页头保存后才写入文件。左侧选择已有动作时提示正在编辑，录下一动作需点“＋新建”。创建、撤销及重做均保留这一状态切换。

本次前端回归共 23 项几何/选择检查及 22 项 DOM 交互场景；独立浏览器页验证第一动作绑定 4 个图元、第二动作绑定 1 个，各次创建后当前选择均归零。临时 QA 动作不保存到用户项目。

### 最新动作显示及前置字段说明

左侧仅在显示时反向遍历创建列表，新建成功后滚动到顶部；底层动作数组、候选/工艺顺序不变。编辑已有动作、搜索或类型筛选不改变创建次序。界面增加明确前置字段的填写说明：仅记录已经确认的严格工序先后，例如在折弯动作中填写必须先冲的异形孔动作编号。邻近、CAD parent 和加工组是不同来源，未自动互填或新增规则。

### 预孔—翻孔加工组自动填写

用户仅确认真实 CAD 关系，不需要手填组号。采集模块以 PRE_PUNCH child → FLANGING parent 的直接关系识别候选；只有对应唯一时才自动归组。自动配对组号统一为 PG_翻孔动作编号，保存配对内部 UID 和 AUTO_CAD_PAIR 来源。旧 PG001 在唯一对应 O008 翻孔时转换为 PG_O008，两名成员同步更名；翻孔改号后组号跟随更新。无法自动匹配的旧明确组保持原记录。

多个预孔候选、编号不唯一或组号冲突时不猜配对；父动作尚未录入时等待补齐。没有按名称、距离、圆形/异形、图元数量、行顺序或编号大小推断关系。改变类型/CAD 关系后清除失效自动组，不改 CAD parent、required_predecessor_ids 或图元绑定。组号是派生采集信息，未改变 H4/H7 定义，也不自动增加 H3。

新增 extract_app/pairing.py 统一实现配对，/api/pairing 提供只处理元数据的预览。读取迁移不写文件；用户保存才增加修订。保存、检查、几何批次指纹及导出统一归一化配对，前端忽略过期响应，避免较慢请求覆盖刚修改的父动作。加工组字段只读，显示对应动作和待确认原因。

验证范围包括自动保存组号、旧组号统一、无 CAD 不猜配对、多候选拒绝猜测、反向 CAD 不倒置、失效清除、过期响应，以及自动组通过原 H1–H7 正式导出入口；具体次数见 outputs/acceptance 下相应检查记录。

### CAD 建议框与父动作临时高亮修正

选取几何会触发编辑面板更新；旧实现每次重建 datalist，加上 SVG pointerdown 的 preventDefault 保留 CAD 输入焦点，造成原生建议框反复弹出。修正后，按下画布明确转移焦点；CAD 输入值没变化时不重复赋值，候选 datalist 仅在动作编号/名称清单变化时更新。真实几何重叠选择器继续保留。

根据当前草稿的 CAD parent 查找唯一父动作，其来源图元增加 cad-parent 显示类，蓝色显示且不受“突出未处理”降透明影响。橙色选择与 hover 保持各自优先级；不加入 selected、不改图元绑定，不推导新关系。输入父编号时即时更新，清空/换父级/新建动作即移除旧高亮。自引用或重复编号不猜父级。

统一组号在读入/检查/保存/导出中执行，记录 group_renames 供审计。既有编号冲突或包含额外成员的旧组不会被擅自拆分。为保留用户正在录入的未保存内容，不在后台直接改写其项目文件；正常“保存标注”会同步写入统一后的组号。

## 选取与来源

- 所有类型允许多条 LINE/ARC/CIRCLE 来源及多个独立轮廓。条数和类型是否匹配，留到整理阶段检查。
- 普通点击追加，再点取消；空白处不清空。框选与同源扩展追加，按源 segment ID 去重。
- 重叠处提供明确列表。多个 DXF 对象即使几何重合，也不按坐标擅自删除来源。
- 跨动作共用图元有提示，须勾选确认。所有相关动作保存显式共用来源记录；未确认的重复绑定在检查中报错。
- 原始图元、原图、源指纹保持原样。显示旋转、缩放和平移只改变显示映射。

## 当前字段与类型

采集项目保留 schema_version=1，新增 workflow_version=2 表示新工作流，不冒充根项目的新 schema。

动作新增 feature_type、geometry_shape、shared_source_segment_ids、no_geometry、bend_source_is_centerline、notes、protrusion_side。原有 CAD parent、predecessor、process group、surface side 继续保留。

feature_type 的页面选项：冲孔—圆形/异形、预孔—圆形/异形、翻孔—圆形/异形、一般折弯/曲线折弯、凸米、拉包、折桥、切边、刻线。PRE_PUNCH/FLANGING 的形状子类不改变其工艺类型。DRAW_FORM 仅为采集层新增类型。

拉包凸起侧使用材料相对 SMOOTH/ROUGH/UNKNOWN。未知不填零、不从相机朝向推断，也不将其当成工具方向。

## 整理行为与适配边界

| 类型 | 整理行为 | 旧下游边界 |
| --- | --- | --- |
| 圆形冲孔/预孔 | 一圈可以由一个 CIRCLE 或多个同心同半径圆弧组成 | 生成现有 CIRCLE；多个独立圈提示检查绑定 |
| 圆形翻孔 | 分开识别多圈，检查同心 | 保留现有圆形表示，不推断各圈工艺角色 |
| 异形冲孔 | 连接并分别记录闭合路径，不补线 | 单轮廓满足旧起始协议才适配 Sheet2；否则保留采集几何，报告待适配 |
| 异形预孔/翻孔 | 保存多条闭合路径和来源 | 当前不强行映射成旧圆形几何，不改变动作类型 |
| 拉包 | 内外闭合轮廓分别记录 | 未推断顶部/底部；内部独立孔不吸收；旧消费端待适配 |
| 一般折弯 | 检查两侧平行直线或明确的真实中线，支持跨间断多段 | 跨度确认后沿用原中线；已确认的轴向矩形区域沿用 Sheet5 |
| 曲线折弯 | 保留全部原始直线/圆弧 | RULE_PENDING；未拉直、拆动作或生成矩形影响区 |
| 折桥 | 检查完整轴对齐矩形，确认后生成原范围表示 | 只收纳范围内未绑定 LINE/ARC；已绑定动作、独立圆孔与跨界片段保留 |
| 凸米/切边/刻线 | 精确保留来源图元 | 沿用既有表示；未推断额外成形几何或三维参数 |

闭合路径使用独立 path_id，保存源图元 ID、有符号圆弧和原始精度。这里的闭合及方向整理不等同于完整制造可行性证明，也不自动建立任何工艺关系。剖面/说明图元可明确标为背景；多视图角色编辑仍属于后续字段设计，未把剖面坐标混入当前二维加工几何。

## 状态、失效与输出

- READY：该采集几何已记录；仍需单独判断 legacy_supported。
- NEEDS_CONFIRMATION：已得到可核对的中线/范围，但跨度、区域等事实需确认。
- NEEDS_REVIEW：绑定不能可靠整理，例如断口、多个独立圆混入一个圆孔。
- RULE_PENDING：表示规则尚未确定，例如曲线折弯。

geometry_complete 与 legacy_compatible 分开。拉包两圈可以记录完整，但不能据此宣称旧候选生成器已经支持拉包。待适配项阻止正式输出，不阻止保存标注或导出检查包。

geometry_batch 记录输入指纹及每动作结果。检查/保存/选取均不运行几何推导。类型、来源、关系、备注、影响区或覆盖记录变化会使批次失效；当前保守地使整批失效，下次显式重新整理。Sheet3/4 导入不改变几何输入指纹。

检查包包括原格式 Sheet1–5 草稿、validation_report.json、source_manifest.json、geometry_review.json 和 annotation_project.json。后两个文件保存多路径、细分类型、未决记录和完整来源。没有完成整理或输入已变化时不导出表格，可以随时保存/下载标注 JSON。

旧项目在内存中迁移，保留全部旧字段、来源与文件指纹；用户主动保存才增加修订。旧已绑定圆形 PRE/FLANGE 可按旧契约迁移；仅导入但未绑定的旧动作不会被假定为圆形。
